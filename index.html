  1. Tudo começa num arquivo.

    O catálogo inteiro fica no data/produtos.json. Para mudar um produto, eu edito esse arquivo, e não as páginas.

    data/produtos.json

    {
  "id": "trident-5s",
  "nome": "Trident 5S",
  "marca": "Mondelez",
  "linha": "Menta, Hortelã, Tutti-Frutti",
  "img": "assets/produtos/mondelez-novo/…"
}

  2. Um script monta as páginas.

    Um script em Node lê o arquivo e escreve o HTML de cada produto e de cada marca, além do sitemap.

    npm run build

    • 333 páginas de produto
    • 19 páginas de marca
    • sitemap.xml e dados estruturados

  3. Cada mudança passa por conferência.

    A cada push, o GitHub Actions confere se o site está em dia com o catálogo e testa os fluxos principais num Chrome sem interface.

    GitHub Actions · verificação

    • Build em dia com o catálogo
    • Nenhum link interno quebrado
    • Nenhuma imagem sobrando
    • Fluxos principais testados no Chrome

  4. E entra no ar sozinha.

    Não tem servidor para cuidar: o GitHub Pages publica o que está na main, com domínio próprio.

    Publicação

    1. push na main
    2. GitHub Pages
    3. distririo.com.br

    De 20 a 60 segundos entre o push e o site novo.

  5. O pedido sai pronto no WhatsApp.

    O comerciante monta a lista no catálogo, informa CNPJ, nome e WhatsApp, e a mensagem abre pronta para enviar.

    Lista de pedido · exemplo

    • Trident 5S
    • Bis
    • Baly Tradicional
